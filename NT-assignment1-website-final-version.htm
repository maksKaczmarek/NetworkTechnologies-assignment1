Protocols Involved in Network Connectivity Verification (Task 2.1)

I. Introduction

The goal of this task was to verify the connectivity to google.com and use Wireshark identify all protocols which were involved in this communication.

II.Execution proof and Command documentation

Image 1

I executed the command ping -n 5 google.com. This command sends 5 packets to the Google server, checks if they are reachable, and measures the time it takes for the packet to return.

The command successfully sent 5 packets and received 4 replies, resulting in 1 packet loss (20% loss). The output (Image 1) notes one request "Request timed out," which confirms the Network Layer (L3) successfully routed the ICMP messages and measured the latency, despite the loss.

III. Protocol dissection and ISO/OSI analysis

Step 1: Name resolution

L7 Application Layer: Domain Name Resolution (DNS): Before pinging the computer has to first convert google.com into IP address like 216.58.209.14 using DNS.

L4 Transport Layer: User Datagram Protocol (UDP): To find out the IP address of google.com the computer sends DNS query to DNS server via UDP on port 53. UDP is chosen because it is connectionless, prioritizing speed over reliability, which is essential for fast, low-latency lookups

Image 2

Step 2: The diagnostic ping

Once when the IP address is known, the system sends the core diagnostic message. This activity is handled by Network Layer protocols.

L3 Network Layer: Internet Control Message Protocol (ICMP): ping sends ICMP echo request packets directly to the IP address acquired in the last step.

Image 3

The Image 3 shows expanded ICMP Echo Request. The header shows that message type is 8 and Code is 0. It confirms that it’s echo request.

 

Image 4

 

The Image 4 shows corresponding ICMP Echo reply. The message type is 0 and code is 0. It confirms the echo reply and proves that target host (google.com) is reachable and successfully responded, therefore verifying connectivity.

From Image 3 and Image 4 we can see that there is no TCP or UDP header above ICMP layer. It proves that ICMP bypasses the Transport Layer (L4) and operates exclusively at Network Layer (L3), because it doesn’t rely on any port numbers.

 

Step 3: Network Foundation

The ICMP packet must be framed and routed by lower layers

Image 5

 

L3 Network Layer: Image 5 shows expanded Internet Protocol Version 4 (IPV4) header encapsulating the ICMP message. The information about Source address (192.168.18.41) and Destination address (216.58.209.14) confirms that Network Layer is responsible for logical addressing and routing.

L2 Data link layer: Image 5 shows header of Ethernet II, where we can see Source MAC Address (Intel…) and Destination MAC Address (HuaweiTechno…). It proves that Data Link layer(including the ARP protocol) handles physical addressing and framing of the packet.

Image 6

 

L1 Physical layer: Image 6 shows expanded Frame header which includes information such as encapsulation type: Ethernet (1), frame length: 74 bytes (592 bits) or unique interface ID. These details confirm conversion from digital data to electric signals proving successful operation on Physical layer.

 

Protocols Involved in Secure File Transfer (Task 2.2)

I. Introduction

The objective of this task was to securely upload an image file to the remote server studife.it.p.lodz.pl and analyze the communication. The file transfer was executed using the graphical client FileZilla, which relies on the SFTP (SSH File Transfer Protocol), operating over the SSH (Secure Shell) tunnel. The analysis identifies protocols across all layers (L7 down to L1), with a heavy focus on the security mechanisms in Layers 5 and 6.

II. Execution Proof and Command Documentation

The secure transfer was executed using the FileZilla client, configured for the standard on-campus port (22).

Step 1: Wireshark Capture Setup

The packet capture was isolated specifically to the host and port required for the connection.

Image 7

The  Image 7 shows that Capture Filter was set to host studife.it.p.lodz.pl and port 22. This confirms Wireshark was correctly configured to filter traffic destined for the server on the standard SSH port (22).

Step 2 : File Transfer Execution

The secure connection was established, and the file was successfully transferred.

Image 8

 

L7 Application Layer: SSH File Transfer Protocol (SFTP): The Status Log shows "File transfer successful," confirming successful execution of the SFTP Application Layer (L7) function. The connection details confirm the use of user ife25_32 and Port 22.

 

III. Protocol Dissection and ISO/OSI Analysis

Step 1: Connection Initiation (L4 Transport)

The communication begins by establishing a reliable connection channel.

Image 9

 

L4 Transport Layer: Transmission Control Protocol (TCP): The transfer relies on the TCP three-way handshake (SYN, SYN-ACK, ACK). This ensures that all parts of the file are sent and received in the correct order without loss.

In Image 9, the first packet shows a TCP SYN request to Destination Port 22, confirming the start of the handshake and proving that the Transport Layer provides reliable and secure data delivery.

 

Step 2: Security Establishment

After the reliable TCP connection is created, the SSH protocol takes over to provide secure communication, working across the Session (L5) and Presentation (L6) layers.

Image 10

 

L6 Presentation Layer: In Image 10, packets labeled “Encrypted packet (len=16452)” confirm that the Presentation Layer applied encryption through key exchange and cipher negotiation. This ensures that the transmitted data remains confidential and protected.

L5 Session Layer: The SSH protocol manages user authentication, session setup, and communication channels, maintaining a stable and continuous connection. This demonstrates the Session Layer’s role in managing and controlling the ongoing secure session.

L7 Application Layer: SFTP/SCP: At the Application Layer, SFTP (or SCP) is responsible for the actual file transfer process. In Image 10, the large, encrypted data segments represent the file data being transmitted, confirming that this layer handles the user-level transfer operations. SFTP manages commands such as copying files and accessing directories, while relying on the secure tunnel created by the SSH protocol at the Session (L5) and Presentation (L6) layers.

Step 3: Network Foundation

Once the secure connection is established, the packets must be properly framed and routed.

L3 Network Layer: Internet Protocol Version 4 (IPv4): Images 9 and 10 display the expanded Internet Protocol Version 4 (IPv4) header. The presence of the Source Address (10.128.102.192) and Destination Address (212.51.220.81) confirms that the Network Layer manages logical addressing and routing, ensuring the secure packets reach their intended destination across multiple networks.

L2 Data link layer: Image 9 shows the Ethernet II header, which provides local physical addressing using MAC addresses. The inclusion of the Address Resolution Protocol (ARP) at this layer is essential, as it resolves the Destination MAC Address before transmission, allowing successful delivery of the packet within the local network segment.

L1 Physical layer: The Frame header visible in Images 3 and 4 demonstrates the conversion of digital data into a raw bitstream that travels through the physical network medium (such as Ethernet cables). This confirms that the Physical Layer is responsible for the actual transmission of the secure packets across the hardware medium.
